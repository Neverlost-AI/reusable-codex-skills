## Portfolio position

Governed Workspace Builder is a reusable Codex skill and deterministic workspace tool that turns a scattered source set into an inspectable project workspace without moving the original files or overstating approval.

It stands apart from Neverlost’s first two Build Week projects:

- **Full Human Pathway** carries complex human evidence across systems.
- **Capacity-Aware Publishing Workflow** governs media production, recovery-aware execution, and delivery.
- **Governed Workspace Builder** governs the project environment itself: custody, source registration, indexing, review states, checkpoints, and promotion.

## The problem

A folder can contain accurate records, polished drafts, outdated plans, contradictory guidance, and private information at the same time. Normal organization tools may sort the files, but they do not establish what each file is, who has authority over it, what has been reviewed, or whether it is safe to reuse.

## The reusable method

1. Initialize a controlled workspace without ingesting source material.
2. Register source metadata and SHA-256 hashes without moving the files.
3. Apply conservative authority and privacy defaults.
4. Generate a central index from machine-readable registers.
5. Separate `working`, `review`, `approved`, and `template` stages.
6. Require human approval metadata before an artifact can become approved.
7. Require a distinct-case retest before an approved pattern can become a template.
8. Append checkpoints with an exact restart step.
9. Validate structure without granting substantive authority.

## Novelty

**Validation and governance are different jobs.**

The validator can confirm that the workspace obeys its contract. It cannot approve the meaning of an artifact, endorse a conclusion, or promote a polished draft into a reusable template. This prevents technical success from being mistaken for human authority.

## Reproducible proof

The synthetic acceptance suite demonstrated:

- `3/3` synthetic sources registered without being moved;
- conservative privacy defaults and an explicit synthetic-public option;
- `0` duplicates created on a repeated registration run;
- an attempted approval blocked without reviewer and approval metadata;
- an attempted template promotion blocked without a distinct-case retest;
- checkpoint history appended rather than overwritten;
- final structural status: `VALID`;
- human approval granted by validation: `false`.

An independent fresh-session test reproduced the source counts, working-artifact lineage, review checkpoint, central index, and authority boundary without access to the development conversation.
